# POI 数字随访管理平台

面向早发性卵巢功能不全（POI）长期管理的医患协同前端原型。

项目当前参加四川大学 2027 年度大学生创新训练计划的**创新类项目**。产业特区子计划 PPT 材料仅作为备选保留，不作为当前申报模板。

> 当前版本为功能原型和技术演示，不是可直接用于临床的真实医疗系统。

## 当前版本

- 演示版本：V0.2.1
- 后端 MVP：`poi-backend-mvp-0.1`
- 最近提交：`6451d3f 调整量表配置并将认知评估移至医生端`
- 默认分支：`main`
- 前端数据：同一浏览器中的 `localStorage`
- 后端数据：独立进程内的合成演示数据
- 运行方式：前端使用 VS Code Live Server，后端使用 PowerShell 5.1

## 产品范围

平台以已确认的临床医嘱为起点，将医嘱审核、随访任务、问卷、复诊提醒和病例消息连接起来。

### 患者端：三个一级模块

1. **上传医嘱**：模拟拍照识别、字段核对和提交医生审核。
2. **干预日历**：查看医生下发的任务、完成状态和截止日期。
3. **病例夹与消息**：查看电子医嘱、原始资料、状态消息和问卷入口。

入口：`v021/app/index.html`

### 医生端：四个一级模块

1. **随访患者目录**：患者检索、基础详情、医嘱审核和患者双视图。
2. **数字医嘱套**：查看标准任务模板并应用到演示患者。
3. **随访数据大盘**：队列规模、随访深度和年龄结构演示。
4. **业务处理大盘**：待审核、复诊、逾期和失访事项演示。

入口：`v021/doctor/index.html`

### 问卷与量表

- `survey.html`：研究团队量表目录，展示腾讯问卷入口。
- `survey-full.html`：完整问卷填写预览，不提交和保存答案。
- `patient-survey.html`：患者端中性问卷壳，不显示具体量表名称。
- Kupperman 仅保留 **13 项版本**。
- CMSS 量表及其入口已删除。
- MMSE、MoCA 不进入患者端问卷，只在医生端患者档案的“认知评估”中提供入口，由医生或研究团队按研究流程施测。

## 演示主线

1. 打开患者端，选择“使用演示医嘱”。
2. 等待模拟识别完成，核对字段并提交医生审核。
3. 打开医生端，完成医嘱审核并下发数字医嘱套。
4. 返回患者端，在干预日历中完成任务。
5. 医生端任务和患者状态随 `localStorage` 同步更新。

患者端和医生端必须通过**同一浏览器、同一站点来源**访问，才能共享演示状态。手机与电脑之间不会自动同步。

## 快速运行

### 方法一：VS Code Live Server

1. 使用 VS Code 打开本目录。
2. 安装并启用 Live Server 扩展。
3. 右键根目录 `index.html`，选择“Open with Live Server”。

### 主要页面

- `/index.html`：演示总入口
- `/v021/`：V0.2.1 双端入口
- `/v021/app/`：患者端
- `/v021/doctor/`：医生端
- `/survey.html`：研究团队量表目录
- `/survey-full.html`：完整问卷草稿
- `/patient-survey.html`：患者问卷入口壳

前端没有构建步骤，也没有第三方依赖。后端 MVP 使用 Windows PowerShell 5.1 自带能力运行。

## 纯后端 MVP

`backend/` 是独立于前端运行的纯后端参考实现，用于验证数据分类、单位权限、分页检索、必要字段返回、患者任务、问卷提交和批次处理。它不读取前端 `localStorage`。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backend\start.ps1
```

服务默认监听 `http://127.0.0.1:8765`。完整接口、演示身份和数据边界见 [backend/README.md](backend/README.md) 与 [backend/API.md](backend/API.md)。

当前后端使用合成数据和服务进程内存储，重启即恢复种子。PowerShell 只是当前演示运行时；正式版仍应采用单体应用、PostgreSQL、院内身份认证和对象存储。Excel 不是本后端的数据源或正式存储方案。

## 当前已实现

- 患者端与医生端的基础响应式界面。
- 单一模拟患者 P001 的医嘱审核、任务下发、患者完成和医生查看闭环。
- 患者任务状态回写、站内消息和未读计数。
- 医生端患者搜索、医嘱审核、数字医嘱套和演示数据大盘。
- 腾讯问卷外部链接目录。
- 41 个编号条目的患者问卷草稿页面。
- 医生端 MMSE、MoCA 认知评估入口。
- 多份研究流程与技术图。
- 独立纯后端 MVP，包含 2 家演示医院、3 个科室、10 位合成患者和 30 个访视。
- 医生、科室、医院、患者和研究人员的数据范围隔离。
- 患者与任务分页检索、字段裁剪、问卷写一次、任务完成幂等和批次任务生成。
- 只增不改的演示审计日志。

## 当前技术边界

- 所有患者、医嘱、检查值、量表分数和任务均为模拟数据。
- `localStorage` 仅可用于原型演示，不得保存真实患者信息。
- 页面中的风险值、状态比例和统计图不代表真实临床结果。
- 平台不自动诊断、不自动开具处方、不自动调整药物剂量。
- 任何真实临床使用前，必须完成后端改造、权限审计、伦理审查和数据安全评估。
- 当前后端没有持久化、事务并发、HTTPS、正式登录、备份或恢复能力，只能处理合成数据。

## 已知问题

- 医生端“待处理”数量在无待办时仍会额外加 1。
- 患者复诊日期标题存在硬编码的“11月24日”，未完全由状态数据驱动。
- 患者问卷尚未回写任务完成状态。
- 患者端和医生端仅支持同一浏览器联动。
- 除 P001 外的患者详情主要是静态展示。
- 文档中的部分研究设计、图注与页面文案仍需统一，例如单中心与多中心、随访节点和样本量说明。

## 本地验证

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\validate-project.ps1
```

检查内容包括：

- 本地 HTML 链接是否存在。
- HTML 元素 ID 是否重复。
- CMSS 和 Kupperman 11 项是否残留。

- MMSE、MoCA 是否误入患者问卷。
