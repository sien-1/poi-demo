# ADR-005：先以纯后端和合成数据验证单位化数据边界

- 日期：2026-11-17
- 状态：Accepted

## 背景

前端原型已经验证患者端和医生端的交互闭环，但数据仍保存在同一浏览器的 `localStorage`。下一阶段需要验证患者目录、单位权限、脱敏返回、分页检索、问卷提交和随访批次处理。当前经费和部署条件不允许先租用较大规模服务器，且项目尚未接入真实患者数据。

Excel 可以作为科室现有业务沟通方式的例子，但不能承担多人权限、并发修改、版本追踪、审计和正式数据治理。

## 决定

- 新增独立 `backend/` 纯后端 MVP，不接入现有前端。
- 使用 PowerShell 5.1 在本机回环地址运行 HTTP + JSON 服务。
- 使用合成种子数据和进程内存储，服务重启后恢复种子。
- 保留正式系统的接口契约、角色权限、分页、字段裁剪、单位关系、批次幂等和审计边界。
- 正式存储明确为 PostgreSQL，不使用 Excel、共享文件或小程序云数据库直接承载真实患者数据。
- 当前不使用微服务，不提前引入 Redis、消息队列或复杂数据平台。

## 理由

- 无需外部运行时可立即执行和验收，适合当前机器和团队条件。
- 可先证明最容易出错的数据边界，而不是重复制作页面。
- 接口固定后，后续替换数据库和登录方式时前端不需要重写业务语义。
- 合成数据可在申报、演示和测试中复用，不接触真实身份信息。

## 后果

- 当前服务不能并发持久化，不能承载真实业务。
- 演示令牌不是正式认证，重启后修改和审计记录会清空。
- 真实数据接入前必须完成 PostgreSQL、事务、身份认证、HTTPS、备份和医院审批。
- 前端暂时仍需使用原 `localStorage` 演示状态；后端联调属于后续独立阶段。
